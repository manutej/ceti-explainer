## What the arsenal is
A pattern library of professional animation capability for explainers, modular so brand, chrome, material,
structure, motion, format and renderer vary independently (INTERVIEW.md Q2). Every entry is a pure module with
a demo page, a card and stills, verified headless.

## Contract for a pattern module  (arsenal/patterns/<id>/pattern.js)
```js
window.ARSENAL = window.ARSENAL || { patterns: {}, structures: {}, materials: {}, brands: {} };
ARSENAL.patterns['<id>'] = {
  id: '<id>', atlas: ['<slug>', ...],
  renderer: 'p2d' | 'webgl',                     // the module's default renderer
  rendererFor(params) { return 'p2d' | 'webgl'; }, // optional: renderer per variant (mass: bars-50000 is webgl)
  params: { /* defaults; every param documented in card.md with its range */ },
  variants: [ { name, params, renderer? }, ... ], // >= 3, showing the RANGE; a variant may name its own renderer
  setup(p, ctx, params) { return state; },       // may be async (return a Promise): font loading, shader compile
  draw(p, t, state, params, tokens) { ... }      // pure of t (seconds); no Math.random/Date/frameCount/millis
};
```
- **setup** is pure of (params, ctx.seed): mulberry32(ctx.seed) for any draw. It MAY be `async`; the demo and every
  host awaits it before the first `seek`, and `__film.ready()` resolves only after it settles. Nothing time-dependent
  happens in setup.
- **ctx** = `{ seed, w, h, tokens }`. `ctx.tokens` is the brand pack, so setup may pre-compute role colours, faces and
  glyph outlines (palette, timeline, mass do). `draw` still receives `tokens` and must honour a pack change, so a
  host may swap packs and re-run setup.
- **renderer** is declared per module and, where it differs, per variant (`variant.renderer` or `rendererFor(params)`).
  The host creates the canvas with it; a module never calls `createCanvas`. Drawing straight on
  `p.drawingContext` (Canvas2D) is allowed in p2d. A module that needs an extra offscreen canvas keeps it out of
  the DOM (`p.createGraphics`, removed or hidden); hosts and shoot.mjs read the main canvas (`p.canvas`).
- **tokens** is a brand pack (arsenal/brands/<id>.json, schema arsenal/brands/schema.json): { id, color: {bg, ink,
  accent, accent2, muted, line, panel, chalk}, type: {disp, mono, body}: {family, weight}, texture:
  'paper'|'none'|'grain'|'halftone', tempo: {ease, beat_s}, voice: {...} }. Modules read ROLES, never hex. Default
  pack: ceti-dark.

## Brand packs in demos (one way)
Demos load `../../brands/packs.js` with a plain `<script>` (it registers every pack as `ARSENAL.brands[id]`; generated by
`python3 arsenal/tools/brand_check.py arsenal/brands/*.json --emit-js arsenal/brands/packs.js`) and select with
`?brand=<id>` (default ceti-dark). No `fetch` of a .json (blocked on file://), no private copy of the packs in the demo.

## Fonts (one way)
Faces come from vendor/fonts.lock.json only. A module that draws type with the canvas `fillText` names the pack's
family (`tokens.type.<role>.family`) and relies on the host having loaded it: kit2 pages embed every lock face as a
WOFF2 data URI (factory/kit2/build.py); demos load `arsenal/fonts/fonts.js`. A module that needs glyph outlines
(`p.loadFont`, `textToPoints`) loads `window.ARSENAL_FONTS['Family|weight']` (TTF data URLs; p5 2.3.4 `loadFont`
refuses WOFF2) inside an async setup. `arsenal/fonts/fonts.js` is shared (moved from patterns/morph-type/fonts; used
by morph-type and particles-text); add a face there (vendor WOFF2 -> TTF with fontTools -> data URL), never a
private copy and never a Google Fonts link. A face that is not loaded falls back visibly: say so in the card.

## Materials (one interface)
The canonical material is the DRAWN interface (arsenal/materials/drawn/materials.js, what kit2 consumes):
`ARSENAL.materials[id] = { mark(p, kind, x, y, w, h, state, tokens), texture(p, box, tokens) }`, kind in
rect | dot | bar | line | arrow | label-underline, state `{seed, i, u, role, a, text}`, p2d, pure of its arguments. Anything else that
transforms pixels after the scene is drawn (shader looks: neon, halftone, chalk-as-GLSL) is a POST, not a material:
`ARSENAL.post[id] = { renderer: 'webgl', setup(p, ctx), apply(p, srcCanvas, t, params, tokens) }`, run by the host
after the scene, never registered under `materials` (arsenal/materials/shader registers as `materials['shader']` today:
it is a post and moves to `ARSENAL.post` when next touched). The exec level (DECISIONS Q6) allows material `ink` and no post.

## Verification (every lane)
`node arsenal/tools/shoot.mjs arsenal/patterns/<id>/demo.html --out arsenal/patterns/<id>/shots` renders each
variant at t = 0, 1/3, 2/3, end, checks re-seek purity (canvas pixels identical), writes a contact sheet and
`shots/report.json`. Shoot at least one light pack too (`--query brand=swiss-grid --out shots/swiss-grid`). Look at the contact sheets yourself once. Fix at most twice. Record seconds per frame.

## Card  (arsenal/patterns/<id>/card.md)
Name; what it is for (one paragraph); when NOT to use; params with ranges; the three variants described; atlas
citations [[slug]] with the S-ids they carry; pitfalls; cost (s/frame at 960×540 ×2 density); renderer; fallback if
any API is beta or unreleased. Under 80 lines.

## Rules
Pure function of t; seeds in setup (async allowed); no runtime fetches; no Google Fonts; vendored p5 only; nothing outside your
folder except what your lane names; no polish rounds; ship with WARNs written in the card. Hand back under 150
words: path, variants, s/frame, what failed.
